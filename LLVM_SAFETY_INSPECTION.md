# LLVM Safety Inspection Report

## Scope

This report inspects the generated LLVM IR for the Vāk string example and the invalid fixed-array example. The inspected files were generated by `vak emit` and accepted by `llvm-as`.

## String runtime example

The string example contains:

```vak
fn main() -> I32 {
  print("hello from Vāk");
  return 0;
}
```

The relevant generated IR is:

```llvm
declare i32 @puts(ptr)
declare void @llvm.trap()

@.str.0 = private unnamed_addr constant [15 x i8] c"hello\20from\20Vāk\00"

define i32 @main() {
entry:
  %t0 = getelementptr inbounds [15 x i8], ptr @.str.0, i64 0, i64 0
  call i32 @puts(ptr %t0)
  ret i32 0
}
```

The string is represented as a private global byte array with a terminating zero byte. The `\20` escapes encode spaces. The `getelementptr inbounds` instruction computes a pointer to the first byte. The pointer is passed to `puts`, and the function returns zero.

This verifies the current minimal string contract. It does not verify ownership, string allocation, string concatenation, string length, UTF-8 validation, or portability beyond the libc ABI used by the native build.

## Invalid array example

The inspected source is:

```vak
fn main() -> I32 {
  let values: [I32; 2] = [1, 2];
  return values[2];
}
```

The relevant IR is:

```llvm
declare void @llvm.trap()

%t5 = icmp ult i32 2, 2
br i1 %t5, label %bounds.ok.3, label %bounds.fail.4

bounds.fail.4:
  call void @llvm.trap()
  unreachable

bounds.ok.3:
  %t6 = getelementptr inbounds [2 x i32], ptr %t0, i64 0, i32 2
  %t7 = load i32, ptr %t6
  ret i32 %t7
```

The comparison is unsigned less-than. An index is valid exactly when it is less than the array length. For index 2 and length 2, the condition is false, so control enters `bounds.fail.4`. The failure block calls `llvm.trap` and cannot continue. The generated executable terminated with exit status 132 on the verification machine.

The valid GEP appears only in the success block. LLVM accepted the complete module through `llvm-as`.

## Valid aggregate comparison

The valid aggregate example contains checks such as:

```llvm
%t7 = icmp ult i32 0, 3
br i1 %t7, label %bounds.ok.5, label %bounds.fail.6
```

The index 0 is less than the array length 3, so the access proceeds to the success block. The example also confirms that array element loads and struct field stores are represented as separate typed pointer operations.

## Findings

| Area | Finding | Status |
|---|---|---|
| String global | Null-terminated private byte array is emitted | Verified |
| String pointer | `getelementptr inbounds` points to first byte | Verified |
| Printing | `print(String)` lowers to `puts` | Verified |
| Array check | Index is compared against length before access | Verified |
| Failure path | Invalid index calls `llvm.trap` and is unreachable | Verified |
| LLVM validity | Generated modules assemble with `llvm-as` | Verified |
| Ownership | No ownership or borrow metadata exists yet | Not implemented |
| String lifetime | Current literals have static module lifetime | Limited bootstrap behavior |
| General pointer safety | Not implemented | Deferred |

## Conclusion

The current LLVM backend provides a real runtime check for fixed-array bounds and a working minimal string-output ABI. These mechanisms are narrower than a complete memory-safety system. They must eventually be complemented by ownership-aware IR, borrow checking, explicit destruction, pointer rules, and a dedicated Vāk runtime library.
